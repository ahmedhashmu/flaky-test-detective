Flaky Test Detective

Finds flaky tests from the JUnit XML your runner already produces, proves which ones are flaky rather than broken, and then makes the flake fail on demand so it can actually be fixed.

Read this before the numbers. The report linked below is built from generated demo data, not from a real test suite. It exists so this page can show working output without asking you to install anything. Its verdicts are genuine output from the same analysis the CLI runs — but the history underneath them was synthesised, so treat it as a UI sample and nothing more.

Sample output — both of these are live

  • The dashboard — the real thing, interactive. Open a test to see its evidence split into proven and inferred, which is the distinction the whole tool is built around. This is the same compiled bundle the package ships, reading pre-generated JSON instead of a live server, so there is nothing running behind it.
  • Analysis report — the standalone HTML export, as flaky report --format html produces it. Single file, no CDN.

Start with the trust score, then click test_large_upload_completes. Note that the order-dependent tests name the test that pollutes them, and that a consistently failing test is labelled broken rather than flaky — refusing to call a real break flaky is the property the tool is most careful about.

The measured claims are elsewhere, and they are real. Accuracy is not self-asserted; it is scored against ground truth and against labels this project did not write. Both are reproducible with one command each.
  • docs/accuracy.md — accuracy against generated ground truth, including the weak numbers. Reproduce with flaky benchmark.
  • docs/real-world.md — scored against developer-confirmed labels from 12 real repositories. Reproduce with flaky validate validation/results.

Point it at your own suite in two commands

What is hosted here is a demo: generated history, baked to static files. The tool itself is local-first and stays that way — it reads a SQLite file on your machine, needs no account, and uploads nothing. That is what makes it safe to run against a private test suite, and it is why the thing above is a pre-generated sample rather than a service you could send your own data to. 

pip install "git+https://github.com/ahmedhashmu/flaky-test-detective"
flaky demo

That builds a populated database and opens the dashboard. To point it at a real suite instead: flaky hunt -n 20 -- pytest tests/ then flaky analyze.

The part worth three minutes

  • Evidence over inference. The primary signal is same-commit divergence: one test, one commit SHA, both a pass and a fail. Measured false-alarm rate 0.0%.
  • It makes the test fail on demand. flaky reproduce delta-debugs your suite down to the smallest test sequence that still breaks the test, then prints the command. CI runs that printed command and fails the build if it passes.
  • It publishes what did not work. One change improved diagnosis 3.5× on generated data and did nothing on real code. That negative result is on the page rather than in a drawer.
